# Append-only baseline - 2026-09-12

SM-105 now assumes growth of the same file identity is append-only. This is the
user-approved simple case: prefix rewrite plus growth requires explicit `--rescan`.
Replacement, shrink and changed metadata without growth still trigger a full import.
Checkpoint v1 rebuilds once into v2. Partial lines reread from the last newline.

Release runtime source is in commit `43ea128`. The measurement started before that
commit: raw metadata records base HEAD `2b48beb` with the working-tree changes,
not a clean build of that base. Binary SHA256:
`a020252318d3b52d1f70cadb7025db618280781732b0b781adbf1dcda96372b6`.
Same Mac16,8, 24 GiB, macOS 27, Xcode 27 beta / Swift 6.4 as the original run.

Corpus: **155 real files, 1,286,230,037 bytes**. Independent copies were captured
from the same selection of live source files; their content has grown since the
[original baseline](2026-09-12.md). Fingerprint:
`9504b4f5ebdc8d898a0ef0b7590f9209d9ac46e3fa278ed74891c2f173c88e2a`.
Three repetitions; OS cache and host memory pressure are uncontrolled. Original logs
and the production database were not modified. These runs do not establish a
controlled before/after speedup.

| Scenario | Wall min / median / max | CPU median | Peak RSS max | Source bytes read per run |
| --- | --- | --- | --- | --- |
| Fresh index | 6.12 / 6.13 / 6.60 s | 6.05 s | 1285.53 MiB | 1,286,230,037 |
| Unchanged | 0.02 / 0.02 / 0.02 s | 0.01 s | 12.20 MiB | 0 |
| Append | 0.02 / 0.02 / 0.03 s | 0.01 s | 13.05 MiB | 752 |

Each append adds **752 bytes** to the same 357,981,056-byte complete source used in
the earlier run. All three imports read **exactly 752 bytes**, resume one file and
skip the other 154. `append.reads_only_delta = true`. The harness now rejects excess
append reads as a failure, including under Python `-O`.

Fresh-import RSS is higher than in the earlier run. Native logs also report peak
memory footprint: first repetition is 1,304,168,032 bytes versus 1,314,391,624 bytes
previously. RSS and footprint are different metrics; the lower historical RSS is
not evidence of a smaller historical allocation footprint. No memory reduction
claim is made for fresh import.

DB + WAL + SHM after writers exit: **4,997,120 bytes** (4,964,352 + 0 + 32,768).
Watch-only CPU was below 0.01 s resolution over 30.0004 s. With an observer over
30.0036 s, watch remained below resolution and observer used 0.02 s (about 0.067%
of one core). No idle emissions; processes stopped cleanly. These short samples
are not a long-term energy estimate.

Independent Python audit matched **6,340 requests** and all six token totals for
`[2026-09-05T05:27:20Z, 2026-09-12T05:27:20Z)`, with zero unknown cache requests.
Append occurred outside that window and left its report unchanged. The entire
incremental report, including sessions and diagnostics, matched a fresh rebuild.

Validation: `make check-core SWIFT_FLAGS=--force-resolved-versions` passed: SwiftLint,
54 core tests and three CLI process harnesses. Tests cover restart, exact byte reads,
partial UTF-8 tails, old checkpoint migration, and explicit rescan recovery after
rewrite-plus-growth. GUI validation is performed by the required GitHub CI gate.

See [methodology](README.md) to reproduce. Private evidence is in the ignored
`.build/sm105-append-baseline/` (`baseline.json`, native timing logs, manifest, audit).
The independent corpus was removed automatically after success; evidence remains.
